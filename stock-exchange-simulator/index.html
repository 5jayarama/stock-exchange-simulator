Speed test

Runs random orders (55% limit, 10% market, 35% cancel) through a fresh book inside your browser and times each one.

Browser timers are coarse, so latency here is rounded. Native benchmarks are in the README.

How it works

  • Price-time priority. The best price fills first. At the same price, the oldest order fills first.
  • Order book. Bids and asks are sorted price levels. Each level holds a linked list of orders, so a cancel is O(1) once the order is found.
  • No allocation while matching. Orders come from a preallocated memory pool.
  • Lock-free queue. The native build can split order intake and matching across two threads with a lock-free single-producer, single-consumer queue.
  • Prices in cents. Integer ticks avoid floating point rounding errors.
Built in C++20, compiled with Emscripten, hosted on GitHub Pages.
